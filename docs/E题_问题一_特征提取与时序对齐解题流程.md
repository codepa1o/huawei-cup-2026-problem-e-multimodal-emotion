# E题问题一：多模态情感特征提取与时序对齐解题流程

> 用途：按本文顺序完成附件1全部100条视频的特征提取、时间对齐、文件交付与论文撰写。本文是实施方案，尚未声称已经完成特征提取或取得实验结果。

## 一、问题边界与最终目标

题目要求以附件1的100条英文原始视频为对象，建立文本、语音、视觉三模态的特征提取与时序对齐模型。`video_id`和`clip_id`共同唯一确定一个样本；`label-100.xlsx`提供转写文本和情感标签。原始样本和标签不可替换、增补、删除或修改。开源工具和预训练模型可以用于基础特征提取，但须记录名称、版本和参数；不得引入其他情感数据集参与训练、微调、参数优化、阈值选择或结果统计。

问题一的完成标准是同时交付以下四类证据：

1. **方法**：说明三模态情感相关特征的定义、提取过程，以及共同时间轴上的对齐规则。
2. **文件**：生成覆盖全部100个样本的特征文件，能从每个输出位置回查原始视频时间位置。
3. **核验**：提供100样本汇总表，并展示至少1个典型样本的词、语音时段、视频帧段及对应特征。
4. **复现**：提供工具版本、模型与参数、运行顺序、日志和异常处理记录。

推荐主线为**原始时间戳 → 统一50个视频时间窗 → 区间重叠加权聚合**。固定50窗均匀聚合作为基线。线性插值仅用于已知时间节点间的数值重采样；PCHIP可作可选对照。Soft-DTW需要可信的跨模态距离，现阶段不列为必做的主对齐算法。

**注意**：附件2的`aligned_50.pkl`是问题二、三可选的已处理特征。问题一的自生成特征可借鉴50位置的接口，但不能把附件2的数值、维度或隐含对齐关系当作附件1的已知真值，也不应在没有同一提取流程证据时宣称两者特征相同。

## 二、实施总览与阶段验收

| 阶段 | 具体动作 | 必须产生的文件或记录 | 进入下一阶段的条件 |
|---|---|---|---|
| 0. 样本清点 | 以标注表建立唯一ID，核对视频路径、可解码性和时长 | `manifest.csv`、清点日志 | 恰好100个唯一ID；每条均找到对应MP4；异常已记录 |
| 1. 提取原始时间信息 | 提取视频帧时间、音频时间、转写文本的词级时间 | 三模态原始时间索引、质量状态 | 时间落在视频有效区间；失败样本有明确状态和退化路径 |
| 2. 提取原始特征 | 使用固定版本工具提取文本、语音、视觉特征 | 原始时序特征、参数清单 | 特征与时间索引同长；维度固定；数值合法 |
| 3. 统一时轴 | 建立50个视频时间窗，按重叠时长聚合 | 50窗特征、源位置映射、各类掩码 | 三模态均能追溯至原始素材；无越界；顺序单调 |
| 4. 基线与核验 | 跑均匀聚合基线，人工检查典型样本，做敏感性分析 | 对照表、对齐展示图、质检报告 | 100样本全覆盖，误差和失败类型已解释 |
| 5. 交付与写作 | 封装特征和说明，核对附件体积与匿名性 | 特征文件、100样本汇总表、复现说明 | 文件可重新读取；总附件不超过50MB；论文能逐项回应题目 |

建议每完成一阶段就保存中间结果和校验摘要，避免最后才发现ID或时间坐标不一致。

## 三、阶段0：建立100条样本的唯一清单

### 0.1 读取和配对

1. 读取附件1的`label-100.xlsx`，保留原始的`video_id`、`clip_id`、`text`、`label`、`annotation`。
2. 使用`sample_id = video_id + "$_$" + clip_id`作为唯一键；视频路径为对应`video_id`文件夹下的`clip_id.mp4`。
3. 核对表中100行、目录中100个MP4、唯一键100个，并逐一检查路径是否一一对应。单独记录多余文件、缺失文件、重复ID，不静默跳过。
4. 从文件容器读取视频/音频流是否存在、可解码时长、视频帧率或逐帧时间戳、音频采样率及起始时间。记录源文件大小与哈希值，供复现核对。

### 0.2 建议的`manifest.csv`字段

`sample_id,video_id,clip_id,relative_video_path,raw_text,label,annotation,video_duration_s,audio_duration_s,video_fps,audio_sample_rate,video_start_s,audio_start_s,decode_status,source_sha256,notes`

`label`和`annotation`只用于样本核对及后续结果分析，**不参与问题一的特征提取、词时对齐或质量阈值选择**，避免把情感答案泄漏到特征中。

**验收点**：100个ID、100个视频、100条输出计划行。任何损坏或短视频仍保留在清单中，随后使用状态码、掩码和文字说明处理。

## 四、阶段1：建立共同的原始时间坐标

令第`i`条视频的有效视频时长为`T_i`，统一将其视频起点设为`t=0`，时间范围为`[0,T_i]`。音频和视频解码时间戳必须转换到这条共同时间轴；如果音频流存在起始偏移，先校正偏移，不能简单假定所有流都从同一时间起点开始。

### 1.1 文本时间

1. 以题目给出的`text`作为唯一原始转写，不用自动识别文本覆盖它。
2. 对音频与给定转写做强制对齐，得到每个词的`(start_s,end_s)`、对齐置信状态及其在原句中的位置。所用工具、声学模型、版本和语言设置均写入配置。
3. 文本编码器如使用子词分词，保存“子词 → 原词 → 词时间区间”的映射。一个词拆成多个子词时，可把该词的时间区间赋给其子词，再对该词的子词向量做聚合；不得假装已取得独立的子词真实时间戳。
4. 若转写与音频严重不匹配或强制对齐失败，保留原文与失败原因。可生成句段级文本特征并标记`alignment_level=utterance`；如采用近似均匀分词作基线，须标记`alignment_level=estimated`，不能作为精确词级证据。

### 1.2 音频时间

从视频中提取音轨，保留采样率及其起始偏移。按固定窗长和步长计算声学帧，每帧保存`(start_s,end_s,center_s)`；遇到静音仍保留对应时间位置。若音频流缺失、截断或不能解码，记录失败状态，不虚构声学特征。

### 1.3 视觉时间

按原视频逐帧时间戳或预先规定的固定采样率抽帧。每帧保留原始帧号、显示时间戳及采样后位置；人脸未检测到的帧保留时间坐标并记录检测失败。不能仅凭固定帧率推测时间戳而忽略可变帧率视频的实际时间信息。

**时间质量检查**：所有时间区间满足`0 ≤ start < end ≤ T_i`（端点允许由解码精度产生的微小容差）；三模态序列按时间单调排列；音频与视频的起止偏移均有记录。

## 五、阶段2：定义并提取三模态特征

先把每个模态的**特征定义、维度、时间粒度、工具版本**写入`config`，再批量运行100条样本。全量样本使用同一套特征方案；局部失败由状态和掩码表达，不临时更换某条样本的特征定义。

| 模态 | 推荐的基础特征 | 原始时间单位 | 必须保存的说明 |
|---|---|---|---|
| 文本 | 给定转写的词级/子词级语义向量；可附情感词或否定词等可解释标记 | 词或子词时间区间 | 编码器名称、版本、检查点、分词规则、层选择、子词到词映射 |
| 语音 | 帧级声学特征，如梅尔频谱/MFCC、基频、能量、发声性；可选预训练语音表征 | 声学帧时间区间 | 采样率、窗长、步长、静音处理、工具及特征维度 |
| 视觉 | 逐帧人脸表情/动作单元/关键点或固定视觉编码器特征；记录人脸检测状态 | 视频帧时间戳或帧区间 | 抽帧率、裁剪规则、检测器与编码器版本、失败帧比例 |

首轮实现宜选**每模态一套稳定且可解释的基础特征**，跑通全部100条后再增加复杂表征。文本语义向量、声学向量和视觉向量的维度允许不同；不要求机械复制附件2的`768/74/35`维度。若采用预训练模型，记录其来源和使用范围，但不在外部情感数据上训练或调参。

将原始输出记为`X_m = {(x_mj, I_mj)}`，其中`m ∈ {text,audio,vision}`、`x_mj`为特征向量、`I_mj`为该向量覆盖的原视频时间区间。抽取后检查特征维度、长度与时间记录是否一致，数值是否包含`NaN/Inf`，并记录缺失或异常原因。

## 六、阶段3：统一50段时间轴与对齐公式

### 3.1 定义时间窗

对第`i`条时长`T_i`的视频，定义`K=50`个半开区间：

\[
B_{ik}=\left[\frac{(k-1)T_i}{K},\frac{kT_i}{K}\right),\quad k=1,\ldots,K.
\]

最后一个区间包含终点`T_i`。使用`K=50`是为了形成稳定接口、便于和题目给出的50位置格式比较；它并不表示附件1原本已有50个真实语义片段。

### 3.2 通过真实时间重叠聚合

对于原始特征`x_mj`覆盖的时间区间`I_mj`，令：

\[
w_{ikj}^{(m)}=\left|B_{ik}\cap I_{mj}\right|,
\qquad
z_{ik}^{(m)}=\frac{\sum_j w_{ikj}^{(m)}x_{mj}}{\sum_j w_{ikj}^{(m)}}
\quad\text{当 }\sum_j w_{ikj}^{(m)}>0.
\]

这里的权重是重叠时长。对只有时间点的视觉帧，先根据相邻帧中点构造其代表区间，或使用“最近时间窗”分配；所选规则必须固定并写清。对文本词使用词起止时间，保存词与50窗之间的多对多权重，而不只保存最终向量。

时间窗无可聚合内容时，特征可填零以保证数组形状，但必须另存掩码和原因。必要的线性插值只用于已知时间点之间的连续数值重采样，不用于补造缺失词或不存在的人脸。

### 3.3 三种状态必须区分

| 状态 | 例子 | 处理 |
|---|---|---|
| 合法的无事件 | 某个时间窗没有说话或没有对应词 | `activity_mask=0`；保留时间窗，不能算作处理失败 |
| 模态观测失败 | 某帧无人脸、音频损坏、文本时间对齐失败 | `observed_mask=0`并记录`missing_reason`；不得与静音混同 |
| 定长存储填充 | 原始变长序列存入固定长度数组，多出的槽位 | `padding_mask=1`并保存`valid_length`；填充值和规则固定 |

本方案的**50个视频时间窗本身都对应真实时间**，通常不需要在50窗尾部补位，因此对齐后数组的`padding_mask`可以全为0。仍需保存每模态`raw_valid_length`、每窗`observed_mask`和`activity_mask`。若另存固定最大长度的原始词/声学帧序列，再对该原始序列使用`valid_length`与`padding_mask`。不能把“没有词的时间窗”误当成padding。

### 3.4 退化方案

当词级强制对齐失败时，仍以视频时间窗组织音频、视觉特征；文本改用句段级特征并注明其只具有句段级时间精度。固定50窗均匀池化可作为完整覆盖的基线。任何退化都应记录样本ID、原因、采用的替代规则及其证据定位限制。

## 七、阶段4：文件设计与全量100样本汇总

可用压缩`NPZ`保存数值特征，以`CSV/JSONL`保存检索表与时间映射。推荐先定义读取接口，再选最终文件格式；不要用只有数组而没有索引的文件交付。

### 7.1 最小交付文件组

```text
problem1_output/
  manifest.csv                 # 原始样本、文件路径与解码结果
  features_aligned_50.npz      # 100条样本的三模态50窗特征及掩码
  source_features/             # 原始时间粒度的自提取特征，按样本保存
  alignment.jsonl              # 每个时间窗映射到词、音频帧、视频帧的记录
  summary_100.csv              # 论文全量结果表的数据源
  processing_log.csv           # 成功、失败、退化和耗时
  config.yaml                  # 特征定义和全部关键参数
  README.md                    # 读取方法、运行顺序、环境与版本
```

最终提交时，须结合竞赛总附件`≤50MB`的限制压缩与裁剪冗余，但保持100样本的全量自生成特征和必要的回溯索引。原始MP4已由题目提供，不重复打包。任何压缩或精度降低须记录数据类型、误差与读取方式。

### 7.2 统一数组接口

`sample_ids: (100,)`；`text: (100,50,d_t)`；`audio: (100,50,d_a)`；`vision: (100,50,d_v)`；`bin_start_s/bin_end_s: (100,50)`；各模态`observed_mask/activity_mask/padding_mask: (100,50)`。维度`d_t,d_a,d_v`由实际提取器决定，并在`config.yaml`中锁定。若某模态提取失败，特征占位和掩码必须同时出现。

`alignment.jsonl`每条建议包括：`sample_id`、`bin_index`、窗起止时间、对应词序号和文字、音频帧索引范围、视频帧索引范围、各来源权重、对齐级别与失败状态。索引必须能回映射到原始素材。

### 7.3 论文的100样本汇总表

至少包含：`sample_id`、视频原始有效时长、音频有效时长、文本词数、原始声学帧数、原始视觉帧数、各模态特征维度、对齐粒度、词级时间戳状态、各模态有效覆盖率、处理状态。正文放可读的全量表，表格原文件随附件提供；如版面受限，正文说明全量表的位置与读取方式，仍确保评委能够核验100条记录。

## 八、阶段5：质量验证与候选方案比较

### 8.1 程序化硬检查

- 样本数恰为100；`sample_id`无重复；原始视频、标注行、输出数组和映射记录一一对应。
- 三模态特征维度固定；时间索引有序且在`[0,T_i]`内；数组无未解释的`NaN/Inf`。
- 每个50窗都能找到视频起止时间；存在特征值时必须有来源索引；观测失败时必须有掩码和原因。
- 原始变长序列的`valid_length`与`padding_mask`一致；每个文件都能被独立读取。
- 使用固定随机种子及相同配置重跑抽样视频，核对哈希或允许范围内的数值差异。

### 8.2 人工核对与图示

至少展示题目要求的1个典型视频；实际开发时建议覆盖短视频、长视频、语速快、停顿多、人脸检测困难等不同情况。把文本词区间、音频波形或能量、视频关键帧、50窗边界叠在同一时间轴，逐项核对是否在正确位置。人工检查记录`sample_id`、发现的错位、修正方式和复查结果。

### 8.3 公平对照

在相同100条视频、相同原始特征和相同50窗下，比较：

1. 固定50窗均匀聚合基线；
2. 时间戳驱动、按重叠时长加权的主方案；
3. 可选的线性插值或PCHIP重采样。

比较指标包括：100样本覆盖率、词/声学帧/视频帧可回溯率、人工抽查的时间偏差、无来源或观测失败窗比例、边界扰动下的结果稳定性、运行时间和文件大小。若没有可靠的对齐真值，应明确将人工抽查误差称为**抽样核验结果**，不能称为全量真实误差。可改变`K`或词边界少量扰动做敏感性分析，但最终提交接口保持同一配置。

## 九、论文写法与最终验收清单

问题一章节建议顺序：

1. **任务和数据**：100条视频、唯一ID、三模态原始材料与不可改动规则。
2. **特征定义**：三模态的具体特征、维度、时间粒度、工具与版本。
3. **数学模型**：共同时间轴、50窗、重叠权重、掩码和退化规则。
4. **求解过程**：从视频解码到文件生成的流程图或伪代码，说明参数和异常处理。
5. **结果与验证**：100样本汇总表、至少1个典型样本可视化、基线对照、错误归因。
6. **复现与限制**：运行命令、环境、模型检查点、配置、日志、附件读取方式；说明词时间戳误差与视觉检测失败的影响。

提交前逐项勾选：

- [ ] `label-100.xlsx`的100行和100个MP4一一对应，原始数据未被改动。
- [ ] 100个样本均有输出记录，失败样本也有状态和原因。
- [ ] 文本、语音、视觉的特征定义、维度、时间粒度与工具版本均已写明。
- [ ] 50窗特征、时间映射、有效长度和各类掩码可以被代码读取并核验。
- [ ] 至少1个典型样本能从词和特征位置回查语音时段及视频帧段。
- [ ] 全量100样本结果表、处理日志、运行说明和自生成特征文件齐备。
- [ ] 不使用外部情感数据训练、微调、调参或统计；预训练提取器使用方式已披露。
- [ ] 所有提交附件合计`≤50MB`，且文件和元数据均无队伍身份信息。

## 十、下一步实施顺序

先实现**阶段0清点脚本**与`manifest.csv`，接着用3条长短不同的视频完成时间戳和三模态特征的试运行。确认输出结构、异常状态和文件体积后，再批量处理100条；最后完成50窗对齐、人工核验、全量汇总与论文写作。这样每一步都有可检查的中间产物，也便于定位失败环节。
