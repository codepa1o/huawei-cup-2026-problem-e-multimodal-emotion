三项关键约束：

1. **保存遮挡前状态**：原`content_support`、结构特殊词元、已知padding、原观测掩码必须保留。人工将token改为PAD后，不能把该缺口重新归类为原始padding或结构词元。
2. **文本向量允许变化**：未遮挡的token ID及位置必须不变，但重编码后这些位置的上下文向量可以改变。只有未遮挡的A/V数值，以及未选中模态的输入，要求保持不变。不得把“未遮挡文本向量完全不变”列为验收条件。
3. **配置单独分层**：当前`problem2.toml`整文件哈希已绑定阶段1—3缓存和checkpoint。新增`configs/stage4_missingness.toml`引用原配置；不要直接往原配置追加增强参数，导致完整缓存整体失效。

阶段4不修改原始数据、stage1/2文件、stage3模型和问题一工程。自己的输出位于`outputs/stage4/<run_id>/`，由配置和输入绑定确定run_id。

## 三、缺失的数学定义与确定性规则

### 3.1 内容跨度与区间

样本i的原内容支持域记为P，保留全部50个官方位置。取非空内容域的首个位置a、最后位置后一位b，定义跨度`L=b-a`。另保留`content_count=sum(P)`，不能把跨度与计数混为一谈。

首轮常规场景要求P在`[a,b)`内连续；实现时先全量检查，不默认所有数据都满足。如果发现内部断裂，记录ID并阻止该样本进入常规场景生成，不压紧位置；未知支持域也不伪造真实缺失率。这不影响阶段2对受损输入的保守适配。

目标比例为`rho_requested ∈ {0.1,0.2,0.4,0.6,0.8}`。明确采用向上半入的长度取整，避免不同语言round规则不一致：

\[
\ell=\min\{L-1,\max\{1,\lfloor\rho_{requested}L+0.5\rfloor\}\},\qquad L\ge2.
\]

起始/中部/末尾的区间起点分别为`a`、`a+floor((L-ell)/2)`、`b-ell`，终点为`s+ell`，统一半开区间`[s,e)`。所有索引均指官方序列位置，不换算成秒。

短样本L<2不能生成常规局部缺失，返回`ineligible_short_support`，原样本保留，不能为了凑数量删掉唯一位置。高比例取整被截到L-1时记录`length_clipped=true`；不将实际比例写成请求比例。

### 3.2 三路保留掩码与实际输入

原输入可用位记为`R0_m = P & O_m`。模态组合选自T、A、V、TA、TV、AV，双模态同步使用同一区间。被选模态在区间内的增强保留位`A_m=0`，区间外为1；未选模态`A_m`全为1。

\[
R'_m=R^0_m\land A_m.
\]

增强不能使原来无效的位置恢复有效；不能改变标签、sample_id或position_index。原观测掩码和增强后输入掩码分开保存，禁止用标准化后的数值重新推断可用性。

### 3.3 三种比例明确区分

设`N_m=sum(R0_m)`、`D_m=sum(R0_m & ~A_m)`：

- `rho_requested`：实验指定的目标比例；
- `rho_interval_actual=(e-s)/L`：实际选中内容跨度比例；
- `rho_actual_m=D_m/N_m`：各模态新增遮挡的原有效观测比例；N_m=0时为null，不写成0%。

另外记录`observed_fraction_storage_after_m=sum(R'_m)/50`，供模型可靠性输入使用，不能把它称为真实内容缺失率。

区间长度小于L，不保证每个稀疏模态仍有观测。若某模态的所有原有效位置刚好位于区间内，允许该模态增强后全空，但必须记录`effective_full_loss_m=true`。这是局部区间对稀疏观测的结果，不等于人为将整模态删除作为默认增强方法。

### 3.4 已有缺失、无效场景和公平比较

将一个组合算作“成功施加”，要求每个被选模态都有原有效观测，且每个被选模态至少新增遮挡一个位置。不能把对全空vision再置零称为新增视觉缺失，也不能把仅T实际改变的TA场景冒称双模态缺失。

- 训练随机位置：在固定模态组合、固定ell下枚举最多50个合法起点，筛出满足上述条件的起点，再均匀抽取；不参考情感标签或模型误差。
- 若某个被选模态原本全空，记录`ineligible_empty_selected_modality`。
- 若没有共同有效起点，记录`ineligible_no_joint_effect`。不偷偷更换模态组合或缩短区间来凑成功率。
- 验证固定位置：绝不为遮到观测而移动起点。固定区间未能使所有选定模态发生新增缺失时，记录`ineffective_fixed_interval`。
- 上述不适用/无效记录仍保存；作为数据加载回退时返回原始输入，`applied=false`，训练实际原始输入比例可能高于50%。本阶段不将样本从原始数据中删除。
- 常规“有效缺失场景”指标只评价`applied=true`记录，并与同一批ID的原始输入预测配对；同时报告分配数、有效数、覆盖率和失败原因。覆盖率为0时指标为null。
- 如输出包含回退记录的全分配集合指标，必须另列`assigned_population_metrics`，不能混入有效缺失指标。跨场景有效样本不同，不能只根据各组准确率差异解释因果规律。

## 四、训练计划与验证计划隔离

### 4.1 训练计划：按epoch确定性变化

初始设定约50%原始输入、50%请求增强；增强组合六种、比例五种。按完整train的ID列表生成每epoch计划，先以固定随机流排列样本，将`floor(0.5*N)`条分配为请求增强，其余为clean。

请求增强的30种“组合×比例”采用均衡轮转再洗牌，分配数最多相差1。原生缺失和短样本会使成功数量失衡，真实分布必须报告，不重采样掩盖失衡。位置在可行起点中均匀抽取。

初始`mask_seed=2026`；从稳定SHA-256派生`split、sample_id、epoch、随机流名称、增强版本`对应的随机数，不使用Python进程随机化的`hash()`，不与模型dropout或DataLoader共用全局随机流。

本阶段保存完整train前2个epoch计划，即6790条分配记录；生成器支持之后扩展epoch。小规模训练取已有256条ID对应的计划行，不重新按小子集生成不同遮挡。不要强求该子集恰好一半缺失。

验收：同输入、配置和epoch计划相同；改变epoch可以改变计划，但短样本或取整可能产生相同mask，不要求每条都变化；打乱DataLoader读取顺序不能改变已分配的遮挡。

### 4.2 验证计划：一次生成、全程锁定

| 计划 | 条件数（含clean） | 728条valid分配记录数 | 本阶段实际用途 |
|---|---:|---:|---|
| quick | clean＋6组合×2比例（0.2、0.6）×中部=13 | 9464 | 全量锁定计划；96条子集试跑评价 |
| full | clean＋6组合×5比例×3位置=91 | 66248 | 生成并校验元数据，供阶段6使用 |

数量包含不适用/无效记录，不保证这些记录均能形成有效缺失。clean不重复当作每个缺失组合下的独立条件。

验证计划不得随epoch、模型种子、模型结构或预测结果变化。quick条件必须与full中同名条件的区间、状态和mask一致，不各自抽取不同样本。验证标签不传入计划生成器；只在预测后的评价阶段读取。

重复掩码使用独立`effective_mask_hash`识别，scenario_id保留组合、比例、位置名称。不同条件映射到相同mask时允许共享计算缓存，但保留条件关联和重复计数；同一视频的多场景副本不是独立样本。

本阶段不据试跑结果更改quick网格或赋权。后续若需要场景等权汇总，应固定权重并报告无有效样本的场景，不能静默重分配其权重。

## 五、增强后的特征处理和缓存

### 5.1 A/V：原位置掩码，固定统计量

复用现有Dataset提供的标准化A/V副本，对新`R'_m=false`的位置置零，其他位置数值不变。等价的原始特征路径为：先建立R'，用既有train统计量transform，再屏蔽无效位；独立测试两条路径一致。

不得用增强样本重新fit均值/标准差，也不得原地写入stage1 memmap。每个视图使用副本，原始视图在多个epoch、多个scenario之后仍保持不变。

### 5.2 T：编码前遮挡，输出后屏蔽

如果T未选中或记录`applied=false`，直接引用完整text缓存。若T有实际新增缺失：

1. 复制原三路整数输入，保留原内容域与结构特殊词元信息。
2. 调用`mask_text_inputs`，遮挡区间的内容token改PAD，attention和segment同步规整，位置不移动。
3. 使用同一revision的冻结BERT重编码整条50位置序列；不读完整text作为替代结果。
4. 输出使用新的文本mask屏蔽；无内容返回全零；不把CLS向量作为“仍然存在文本”的证据。
5. 未遮挡token的上下文向量可以改变；验收检查的是模型输入与遮挡后的上下文一致性，而非要求其保持原向量。

现有接口使用的`augmentation_keep_mask_m`、新的input_mask与原始mask同时输出，便于追溯和后续阶段5可靠性计算。

### 5.3 按内容哈希复用，避免缓存爆炸

完整stage1缓存只读。缺失text缓存另建，以处理后的三路整数输入、内容mask、编码器/词表版本、层、dtype和接口版本计算键；增加payload哈希验证损坏。相同文本区间在T/TA/TV条件间可以共享文本向量，scenario归属另存映射。

首轮CPU、float32、batch=8、4线程、num_workers=0；冻结编码器只初始化一次。不在Dataset每次取样时重复加载BERT，也不把BERT实例复制给多worker。

推荐有限分片NPY/memmap＋索引清单，不为每个场景复制一套T/A/V大数组。A/V在取样时轻量施加mask，文本实际需要时编码，提交顺序沿用“特征→哈希→完成位”，并保留Windows有界文件占用重试。

- quick验证理论最多`728×2=1456`种新增文本输入，T/TA/TV共享；float32文本上界约213 MiB，短样本、重复/无效条件会降低实际值。
- full验证理论最多`728×5×3=10920`种新增文本输入，约1.56 GiB；本阶段只生成full计划，不预先物化这些特征。
- 训练本阶段只物化256条子集、2个epoch中实际需要的文本缺失输入；完整train计划保留为元数据，正式训练时按需处理。
- 估算不含完整缓存、索引、模型、临时写入空间；先用3条代表样本测耗时、峰值/结束内存，再确定批处理运行预算，不承诺沿用上一阶段的固定耗时。

为后续同场景快速验证准备全728条quick所需的唯一文本缓存，但本阶段仅对96条子集做预测评价，二者状态分开记录。

## 七、小规模试运行顺序

1. **预检**：重新验收阶段1—3输入绑定，检查完整P是否连续，读取125条视觉全空记录，禁止读test或附件3进行增强调参。
2. **合成检查**：覆盖L=0/1/2、内部和末尾缺口、原生全空/稀疏模态、TA/TV/AV共同区间、无共同有效起点和重复mask。
3. **三样本真实检查**：复用内容长度1、20、48的代表样本。长度1必须不可行回退；另外两条检查连续性、实际比例、文本重编码及原值保护。
4. **生成并锁定计划**：全train前2个epoch、728条valid的quick与full计划；生成覆盖率与重复统计。不因看到预测效果而重排计划。
5. **试跑所需编码**：先生成256条train和96条valid所需的唯一缺失文本；固定A/V统计量。
6. **B1集成试跑**：复用阶段3的256/96子集、seed、hidden=64、2个epoch、优化器参数，从头初始化一个B1进行混合输入训练，不直接续训阶段3模型。作为对照，读取阶段3已训练B1，以同一96条子集和13个quick条件评价两者。
7. **评价口径**：各模型每个条件保留96条分配记录，理论每模型1248条、两模型2496条预测记录；有效缺失指标仅用applied子集，clean用全部96条，另报覆盖率和同ID配对clean。无有效条件为null，不能报伪0分。
8. **补齐quick输入与交付核验**：通过小试后，仅补齐全728条quick唯一缺失文本缓存；不做全728正式评价，不物化full特征。生成本阶段独立报告。

本阶段的增强B1与原始B1对比用于检查集成与数据路径，不据此宣布某种缺失训练必然有效。正式选型与全量模型训练仍属于阶段5—6。

## 八、独立测试与验收门槛

| 检查 | 通过标准 |
|---|---|
| 区间连续 | 被选模态A的零区间恰为一个半开区间，索引不压紧；无效记录不施加 |
| 范围与取整 | 合法局部区间长度在1到L-1；请求/实际比例及截断状态可追溯 |
| 模态选择 | 未选模态不变；双模态共用区间；增强后有效mask不超过原mask |
| 原生缺失 | 原N=0返回null比例且不能标成功；不删除样本或换组合凑数 |
| 文本不泄漏 | 仅被遮挡词不同的两输入，遮挡后整数输入、编码及eval预测在容差内一致 |
| 值保护 | token未遮挡位置不变；A/V未遮挡位置不变；文本重编码允许上下文变化 |
| 支持域保护 | 人工缺口不会成为“原始padding”；原P/特殊词元/观测状态不被覆盖 |
| 统计量隔离 | 原normalizer和label_priors文件哈希不变；增强没有调用fit |
| 标签无关 | 生成器不接收标签；交换标签不改变计划；未把标签拼入输入 |
| 随机流隔离 | 改模型seed、读取顺序不改valid计划；相同mask_seed/epoch重建一致 |
| 缓存正确 | 同遮挡输入可共享；不同输入不会命中完整文本缓存；损坏行可识别重算 |
| 配对公平性 | 所有模型同scenario对应相同ID、mask与适用状态；覆盖率可复算 |
| 无副作用 | stage1/2/3原产物校验通过；不覆盖原始模型/缓存/报告 |
| 训练可用 | 损失/梯度有限，参数确实更新，概率合法、强度有界、保存加载一致 |

文本编码和预测浮点容差首轮沿用`atol=1e-6, rtol=1e-5`；索引、mask、token与哈希要求精确一致。结果无提升不算软件验收失败，信息泄漏或状态误标必须阻止放行。

## 九、实施批次与完成定义

| 批次 | 工作 | 放行条件 |
|---|---|---|
| 1 | 独立配置、输入绑定、缺失纯函数 | 短样本/原生缺失/三路mask测试通过 |
| 2 | 确定性计划生成与固定验证场景 | 数量、覆盖率、重复、标签无关检查通过 |
| 3 | 增强视图和文本缓存 | 真实三样本无泄漏、值/位置保护通过 |
| 4 | 256/96的B1混合输入试跑 | 训练、配对预测、加载复现通过 |
| 5 | 全quick唯一文本准备和最终核验 | 计划/缓存/报告齐全，阶段1—3产物未变 |

完成阶段4后应得到“可重复的缺失输入生成器＋固定验证场景＋文本无泄漏证据＋模型接入试跑”。这时再规划或实现阶段5的时序编码与动态门控，不需要重写前述缺失规则。
