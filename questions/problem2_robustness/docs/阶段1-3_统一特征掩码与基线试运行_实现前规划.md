## 三、阶段1：统一特征接口与官方序列位置

### 3.1 统一数据对象

加载器按明确的split与sample_id取样，不依赖DataLoader打乱后的顺序关联标签。建议样本对象如下：

| 字段 | 单样本形状／类型 | 说明 |
|---|---|---|
| sample_id、split、source_row_index | 字符串、字符串、整数 | 源数据身份与原顺序 |
| input_ids、attention_mask、token_type_ids | 各(50,)，int64 | 官方整数输入，不重新排列token |
| position_index | (50,)，int64 | 固定0—49，可共享保存 |
| text | (50,768)，float32 | 统一编码器生成的上下文向量 |
| audio、vision | (50,74)、(50,35)，float32 | 官方数值特征的处理副本 |
| support与observation字段 | 见阶段2 | 不通过标准化后的零值倒推 |
| class_label | int64，可空 | 仅有标签划分使用 |
| regression_label | float32，可空 | 同上 |
| source／encoder版本 | 元数据引用 | 哈希和配置绑定 |

类别与连续标签不传给文本编码器，也不拼入特征。无标签样本应能通过同一接口返回`label_available=false`，不使用0作为“标签缺失”占位而参与损失。

### 3.2 文本编码兼容门槛

在大批量下载权重或编码前，先取得基础BERT对应分词器元数据／词表，检查：

1. 词表范围、PAD／CLS／SEP等特殊ID及大小写规则匹配。
2. train／valid原文按候选分词器重建序列，对比官方ID、attention_mask和segment输入；最大长度50、特殊词元和截断规则明确。
3. 完全匹配数量、仅padding差异、可解释的文本预处理差异和未知差异分别记录；抽样列出差异位置和原始token。
4. 未解释的非特殊token映射或位置偏移必须解决，不能按任意“匹配率达标”放行；若问题来自原文与官方ID不一致而非词表，保留官方ID及差异证据，不用重分词结果覆盖源序列。
5. 以核验通过的确切词表和模型revision固定配置。模型权重获取、验证和加载状态分别记录。

产物：`tokenizer_audit.csv`、`tokenizer_audit_report.json`、`encoder_manifest.json`。模型来源和revision在后续实际获取时填写，不在规划里虚构提交号。

### 3.3 编码与位置规则

- 使用基础编码器的最后一层hidden states，形状为(B,50,768)，无分类头；设eval并关闭梯度。
- 编码器attention_mask包括合法特殊词元；局部内容池化掩码排除PAD／CLS／SEP等已核实特殊词元。
- 文本编码后将不属于当前可用内容的位置置零，同时保存原始整数输入、原始attention_mask和特殊词元记录。
- 音频／视觉与文本按官方位置对齐，保留首尾特殊位置、padding和内部缺失的原始槽位。
- 不把“50行形状一致”表述成已取得逐词秒级真值。位置图使用索引或相对序列位置。

### 3.4 为阶段4预留的最小编码入口

`encode_text(input_ids, attention_mask, token_type_ids, content_observed_mask)`必须接受已经遮挡的输入，不仅接受样本ID查询完整缓存。

本轮可实现一个确定性测试辅助函数：把指定区间的token ID替换成PAD、对应attention_mask置0，保留其他位置及合法特殊词元，再重新编码并施加输出掩码。它用于确认编码接口支持未来缺失增强，不实现随机训练增强系统。

缓存键包含处理后的三路整数输入、内容掩码、模型／词表revision、层和dtype。后续缺失文本不得命中完整文本缓存。输入无有效文本内容时直接返回全零文本特征和不可用状态，避免全空attention产生未定义行为；有内容但必要结构词元损坏时记录输入状态并按预定适配规则处理，不恢复被隐藏的原词。

### 3.5 缓存与批处理策略

先对3条代表样本编码，测量耗时与内存；再准备小规模试运行所需样本。端到端检查稳定后批量生成全部train与valid缓存。

缓存按split保存为可内存映射的NPY数组与JSON／CSV索引，不写一个需要反复整包解压的大NPZ。数据示例：

```text
outputs/stage1/
  encoder_manifest.json
  tokenizer_audit.csv
  tokenizer_audit_report.json
  train/
    sample_ids.json
    input_ids.npy
    attention_mask.npy
    token_type_ids.npy
    text.npy
    audio.npy
    vision.npy
    labels.npz
    cache_meta.json
  valid/                         # 同结构
  pilot_manifest.csv
  run_report.json
```

train＋valid的float32文本数组约604 MiB，此为按4123×50×768×4计算的体积估算，不是实际运行测量。另需音频、视觉、源PKL和模型内存。首次加载PKL只读取一次，避免多worker各自复制约1GB源文件；DataLoader首轮`num_workers=0`，文本编码批大小从8起测。实际耗时以3条及小批次测量为准，不承诺固定分钟数。

缓存采用临时路径写入、完成后提交完成标志；sample_ids、输入哈希或encoder配置变化即失效。恢复未完成任务时核对行号和输入哈希，不把存在文件等同于缓存已完成。

**阶段1验收**：train／valid全量缓存4123条，输出float32且有限；ID与原顺序相同；没有时间位置平移或压紧；3样本重复编码一致；词表兼容有证据；修改遮挡输入后不会复用完整文本向量。

## 四、阶段2：掩码、有效长度与标准化

### 4.1 各类掩码独立保存

所有下列掩码用bool，形状为(50,)；不复用一个mask表达所有语义。

| 字段 | True的含义 | 生成方式 |
|---|---|---|
| content_support | 已确认或采用的内容支持位置 | 完整样本attention_mask排除特殊词元，并核查A/V来源 |
| special_token_mask | 特殊词元位置 | 已验证的词表ID |
| padding_known_mask | 已确认的填充位置 | 完整输入的原始attention_mask及编码约定 |
| support_unknown_mask | 内容／padding无法确认 | 受损输入中缺少可靠长度证据的位置 |
| text_observed_mask | 当前文本内容可用 | 原始有效ID、attention与特殊词元约定 |
| audio_observed_mask | 原始音频有限且整行非零 | 在标准化前建立 |
| vision_observed_mask | 原始视觉有限且整行非零 | 同上 |
| augmentation_keep_mask | 本次增强保留位置 | 本轮全True；测试可指定缺口 |
| input_mask_m | 模型实际使用该模态的位置 | 操作性支持域×观测×增强保留 |

已知padding和特殊词元不能被视为缺失证据。原始观测全零属于“不可用”的操作性判定，不据此推断静音、遮挡或缺失的真实原因。标准化后恰好为零的有效向量仍是有效观测。

### 4.2 内容域已知与未知两类入口

附件2完整输入以官方文本结构建立内容支持域，并检查音频／视觉非零行均被覆盖；前轮train／valid通过了这项检查，后续代码要重新固化该证据。人工遮挡测试保留遮挡前支持域，不重新推断长度。

对于受损、无可靠长度的样本：各模态观测掩码独立生成；任一模态有可信观测的位置不得被当前文本attention_mask误删。不能以“最后一个非零位置”确认padding。保留50个槽位，在无法证明padding的位置设置unknown；如按观测并集包络提供估计跨度，保存`support_source=estimated`与估计值，并明确不代表真实长度。

本轮这类规则先用合成受损样本验证，并做附件3schema兼容，不批量分析专项缺失模式或输出预测。实际输入的未知支持域处理使用同一固定策略。

### 4.3 有效长度与模型可靠性输入

每样本保存下列数值，避免把不同“长度”混为一谈：

- `storage_length=50`；
- `content_length`：已知内容位置数，未知时为null；
- `content_span_start/end`：已知或估计包络，索引半开区间；
- `observed_count_m`：当前各模态可用位置数；
- `observed_fraction_storage_m=observed_count_m/50`；
- `observed_fraction_content_m`：仅内容长度已知时计算，未知时为null；
- `support_source`与`support_unknown_count`。

当前基线采用`observed_fraction_storage_m`与`available_m`作为辅助输入，分母固定为50，以保证受损专项输入的可计算性；报告中称“存储位置观测比例”。内容域内可用率保留在审计表，不用估计值冒充已知缺失率。

### 4.4 数值异常和训练集标准化

音频／视觉仅在train原始可用行计算每维均值和总体标准差，使用float64累计，再保存到指定精度。有效行先用布尔索引筛选；不能靠`mask*NaN`消除非法数值。

实现规则：

1. 原始NaN／Inf记录样本、模态和位置，默认记error，在配置没有明确获准的隔离规则前不继续正式准备。
2. 训练统计量分母是有效观测数，不是N×50；验证数据永不参与fit。
3. 标准差下限建议1e-6；标准差低于该值的维度标记为常量／近常量维，缩放因子固定为1，保留该列。无有效观测的模态或维度为错误，不偷偷补正常统计量。
4. 变换为`(x-mean)/scale`后，不可用位置再次置零，原始mask保持不变。
5. 文本只做模型内LayerNorm／投影，不额外拟合验证或全数据文本统计量。
6. stage1缓存保留处理前A/V，stage2生成统计量与掩码；标准化由Dataset或collate按批执行，不重复保存一套全量标准化特征。

保存`normalizer.npz`与`normalizer_meta.json`，含fit_split=train、有效计数、均值／scale、常量维列表、源／配置哈希和拟合时间。

## 五、阶段3：最小基线与小规模试运行

### 5.1 本轮只实现B0与B1

统一掩码均值池化：

\[
v_{im}=\frac{\sum_{k=0}^{49}R_{imk}\widetilde X_{imk}}{\max(1,\sum_{k=0}^{49}R_{imk})}.
\]

全空模态返回零向量与available=0。均值池化忽略位置顺序，是有意设置的低复杂度基线；后续时序模型在同一接口上比较是否有收益。

| 名称 | 模型输入 | 下游结构 | 用途 |
|---|---|---|---|
| B0-T | 文本池化向量＋该模态观测比例／available | Linear→ReLU→Dropout→分类／回归双头 | 文本基线 |
| B0-A | 标准化音频池化向量＋两项状态 | 同上 | 音频基线 |
| B0-V | 标准化视觉池化向量＋两项状态 | 同上 | 视觉基线 |
| B1-TAV | 三路池化向量拼接＋三路观测比例／available | 同类MLP，hidden=64 | 多模态拼接基线 |

各模型可先对自己的文本池化块应用LayerNorm，A/V已经标准化。LayerNorm或投影有可训练偏置时再用available屏蔽无效分块，避免空模态产生伪表示。记录模型参数量，不声称不同输入维度的基线参数完全相同。

分类头输出3个logits，回归头为`3*tanh(linear(h))`。类别按概率argmax映射为Negative／Neutral／Positive，中性不依赖回归输出恰好等于0。

全部输入模态无可用观测时，预测使用train类别先验与train强度均值，并记录`all_inputs_unavailable`；该回退可应用于单模态模型的空输入。不把先验输出当作正常多模态推理。

### 5.2 损失与试运行参数

采用训练集类别频数加权交叉熵与Huber回归损失：

\[
\mathcal L=\operatorname{CE}_w(logits,c)+\operatorname{Huber}_{\delta=1}(\hat y,y),\qquad
w_c=\frac{N_{train}}{3n_c}.
\]

使用train全量标签拟合类别权重及回退先验，保存来源与计数。基线阶段不加一致性损失、动态门控或随机缺失增强。

| 参数 | 初始规划值 |
|---|---|
| 文本编码设备／dtype | CPU／float32，冻结 |
| 文本编码batch_size | 从8试起，依实际资源确定 |
| MLP hidden_dim | 64 |
| 试运行batch_size | 16 |
| 优化器 | AdamW，lr=0.001，weight_decay=0.0001 |
| Dropout | 小规模训练0.1；过拟合诊断0 |
| 训练／抽样种子 | 2026，写入配置 |
| 小规模epoch | 2 |
| 梯度裁剪 | norm=1.0 |

以上是工程试跑设定，不作为已验证的最佳超参数。当前阶段固定2个epoch，报告每轮valid指标，保存最终epoch及恢复测试产物；不做广泛选型或test评价。

### 5.3 分四层试运行

**A. 三样本特征检查**

从train按确定性规则选择短／中／长且尽可能覆盖三类标签的3条样本，保存实际ID、选择依据和内容长度。冲突时明确优先级，不反复挑选表现好的样本。打印少量特征摘要、掩码、源索引与形状，重复编码检查一致性。

**B. 合成边界检查**

覆盖：合法无缺失、内部连续缺口、末尾缺口、仅一个可用位置、单模态全空、全部输入全空、不同模态有效位置不一致。至少检查一次文本“被遮挡词不同、遮挡后有效输入相同”的编码及预测一致性。模拟数据只用于软件检查，不加入真实训练或指标报告。

**C. 32样本过拟合诊断**

从train分层抽取约32条样本，关闭Dropout，用B1进行最多200个梯度更新；记录loss初末值、有限性、梯度和参数变化。损失不明显下降时先检查输入、标签、掩码与优化步骤，不继续批量运行。可将末尾20步平均loss较前20步下降至少20%设为诊断触发线；未达线即查因，不通过反复更换样本规避。该阈值只衡量工程学习链路，不是预测性能门槛。

**D. 小规模端到端训练**

固定train子集256条、valid子集96条，按原划分内类别比例分层抽样并保存ID，任何样本不跨官方split移动。四个基线共享这两份子集，每个运行2个epoch，得到训练曲线、验证指标、逐样本预测与样例CSV。

子集试跑的A/V标准化仍只由完整train有效观测拟合，在日志注明“下游训练256条，预处理拟合3395条”；它不是独立的小样本学习实验。不得把试跑性能当作完整728条验证集性能或最终模型性能。

先按A→B→C→D确认管线，再批量补全stage1／2的train与valid产物，复查全量数据契约。本阶段结束时得到全量可训练输入与小规模基线证据，后续全量训练无需重做已冻结的完整输入编码。

### 5.4 指标、预测与checkpoint

指标统一为Accuracy、Macro-F1、MAE、Pearson。固定三类混淆矩阵，分母为0时分类精确率／召回率按已声明规则记0；Pearson遇到真值或预测无方差、样本不足2条时保存null与原因，不写NaN或伪造0分。

可使用既有NumPy／SciPy和PyTorch完成这些小规模指标，并用手算混淆矩阵及独立相关系数计算核对；不引入新的大型训练框架。报告包含样本数、split、subset哈希、模型名、epoch、种子与四指标。

样例预测来自valid子集，字段为：

`sample_id,split,model,seed,true_class,true_intensity,p_negative,p_neutral,p_positive,predicted_class,predicted_intensity,prediction_status`

模型checkpoint保存模型参数、结构配置、优化器状态、epoch／step、随机状态、编码器引用、标准化／标签映射／数据／子集配置哈希。冻结BERT基础权重由encoder_manifest引用，不在每个checkpoint中重复保存。

在新加载的模型对象上重算固定批次，核对预测与导出前一致；若提供断点续训功能，还需以固定batch验证下一步更新一致。推理复现使用CPU float32、eval模式与固定容差，如`atol=1e-6, rtol=1e-5`，超限须查因。

## 七、实现顺序与验证安排

| 批次 | 先完成的工作 | 检查／放行条件 |
|---|---|---|

| 7 | 全量产物检查、运行报告与README | 用户可按记录复跑并定位失败环节 |

阶段编号表示交付职责，不要求等全量BERT编码结束才检查最小训练闭环。实现过程中少量样本先贯通，之后再补全批处理，以减少返工。

独立验证重点：

1. **标准化无泄漏**：同一train加两份不同valid，拟合产物必须相同；增加padding不得改变训练统计量。
2. **位置不变**：遮挡内部区间后，下一个有效token／A/V行仍保留原position_index。
3. **文本不泄漏**：改变将被遮挡词的ID，应用同一遮挡后输出一致；缓存键也应一致或不会引用原完整向量。
4. **掩码真实生效**：修改mask=0位置的有限占位值，不改变对应池化结果；有效零值不被自动删除。
5. **指标独立复算**：固定小矩阵手算Accuracy／Macro-F1，回归样例独立计算MAE／Pearson。
6. **预测可复现**：保存加载后的概率、强度和sample_id排列一致。

## 八、风险、处理规则和完成定义

| 风险／不确定性 | 处理规则 | 对范围的影响 |
|---|---|---|
| 阶段0尚无产物 | 将最小审计作为第一批实现 | 不跳过前置数据契约 |
| BERT未缓存、CPU较慢 | 词表先验收，3样本测资源，分批缓存与断点恢复 | 具体耗时实测后报告 |
| 原始文本无法完全重现ID | 区分词表不兼容与原文预处理差异，记录证据 | 未解释位置／词义错误阻止正式编码 |
| 专项长度与padding不可辨识 | 固定50槽位、独立观测掩码、unknown标记 | 不承诺恢复真实缺失秒数 |
| 全零与NaN被错误混同 | 全零按观测规则，非有限值单独错误定位 | 不静默清洗后称正常 |
| CPU加载全量数据内存增加 | 单次源读取、float32副本、memmap、num_workers=0 | 不加载非对齐大文件参与本轮训练 |
| 试跑指标被误认为最终结果 | 输出名及报告注明pilot、子集和epoch | 最终性能留待全量验证 |
| 缓存／模型配置过期 | 用哈希绑定，缺失或不匹配时拒绝复用 | 不混用旧特征和新标准化 |

完成本次实现后，应该能够明确回答：

- train和valid的4123条输入是否采用同一编码器、保留原50位置并能追溯？
- padding、特殊token、观测失败、未知支持域和标准化是否按统一规则处理？
- 四个最小基线能否在固定小子集训练、评价、保存、重新加载和导出？
- 后续连续缺失增强能否通过同一编码入口进入模型，而不泄漏被隐藏词？

上述四项有可检查产物后，即可进入阶段4连续缺失增强与阶段5动态门控训练；本阶段不以达到某个预设准确率作为完成条件。
