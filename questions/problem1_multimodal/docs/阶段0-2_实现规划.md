# 问题一阶段0—2：实现前规划

## 1. 目标、范围与当前证据

本工程只处理题目附件1的100条原始视频。阶段0建立准确的样本清单；阶段1建立统一到视频起点的文本、音频、视觉时间坐标；阶段2提取仍保留原始时间粒度的三模态特征。阶段3的统一50窗聚合在上述数据契约稳定后再实现。

已核对的输入事实：

- 附件1的实际样本根目录是“MOSEI数据集部分原始视频-100条”内层目录；该目录含100个MP4、一个100行标注表，视频分布在37个 video_id 子目录。
- 标注表列为 video_id、clip_id、text、label、annotation；实测这五列读取后均是字符串。clip_id 必须按字符串处理，例如“13”不能经过浮点转换变成“13.0”。
- video_id 与 clip_id 共同定位视频；样本ID按赛题附件2格式写为 video_id$_$clip_id。
- 原始附件不得改写；label 和 annotation 只用于身份核对与后续分析，不能作为特征提取、强制对齐、阈值选择的输入。
- 当前检查用的 Python 3.12 环境可导入 openpyxl、numpy；当前系统路径找不到 ffmpeg/ffprobe，也未安装本方案需要的语音/视觉/文本提取依赖。这是环境检查结果，不代表机器上绝对不存在这些工具。

实施原则：先完成100条的身份与媒体质量清点，再选定提取器；先让3条代表视频贯通阶段1—2并验证文件契约，再批量运行100条。每个阶段都保存失败状态，不能静默丢弃样本。

## 2. 工程与数据流

建议后续代码保持少量脚本，不引入额外框架：

| 后续脚本 | 输入 | 主要职责 | 输出 |
|---|---|---|---|
| src/build_manifest.py | label-100.xlsx、MP4目录、project.toml | 身份配对、媒体探测、哈希和异常清点 | outputs/stage0/manifest.csv、issues.jsonl |
| src/build_timeline.py | manifest.csv、原MP4、原转写 | 统一视频/音频PTS、词级强制对齐、视频帧时间索引 | outputs/stage1/timelines/、status.csv |
| src/extract_features.py | manifest.csv、timelines/、原MP4 | 文本、语音、视觉原始序列特征 | outputs/stage2/features_raw/、feature_index.csv |
| src/validate_outputs.py | 各阶段输出 | 检查100条覆盖、时间边界、维度、掩码和数值合法性 | outputs/validation/ |

目录只负责项目代码与生成结果；原始数据通过相对路径读取。建议用一个配置文件固定路径和初值；选定的模型名称、检查点版本、工具版本与最终参数在试运行后追加到配置与运行日志。程序运行时解析相对于**工程根目录**的路径，不依赖调用命令时的当前工作目录。

生成结果按阶段保存：

    outputs/
      stage0/manifest.csv
      stage0/issues.jsonl
      stage1/timelines/<video_id>/<clip_id>.json
      stage1/status.csv
      stage2/features_raw/<video_id>/<clip_id>.npz
      stage2/feature_index.csv
      validation/

使用 video_id/clip_id 双层目录保存逐样本文件，避免只用 clip_id 造成重名。所有输出必须含 sample_id，便于直接联表。任何模型权重或解码临时媒体放在单独的工作缓存中，不修改原附件，也不混入最终提交附件。

## 3. 阶段0：建立100条样本的唯一清单

### 实现步骤

1. 用 openpyxl 以只读模式读取 label-100.xlsx；检查必需列恰好可识别，保留原始字符串及标注表行号。原始 text 不做覆盖式清洗；如以后为对齐器做规范化，另存 normalized_text 和变化记录。
2. 为每行构造 sample_id = video_id + "$_$" + clip_id；查找配置所指样本根目录/<video_id>/<clip_id>.mp4。对实际视频文件反向检查，找出“表中无视频”和“视频无标注”两类问题。
3. 对每个MP4计算文件大小和 SHA-256，使用 ffprobe 读取视频与音频流是否存在、流时长、起始PTS、帧率与采样率。媒体探测失败也保留 manifest 行，错误写入 issues.jsonl。
4. 核对标注数、MP4数、唯一 sample_id 数、重复标注、缺失路径、多余文件以及可解码数量。异常不得在内部自动删除、替换或合并。
5. 输出UTF-8 CSV。字段中的标签数值保留原始字符串；如后续要用连续情感值，应另设解析字段，不能覆写原列。

### manifest.csv 合同

必需列：sample_id、source_row、video_id、clip_id、raw_text、label_raw、annotation、relative_video_path、file_size_bytes、source_sha256、video_stream_status、audio_stream_status、video_start_pts_s、audio_start_pts_s、video_duration_s、audio_duration_s、fps_reported、audio_sample_rate_hz、probe_status、issue_codes。

时间字段使用秒；无法读取时留空并给 issue_codes，不填0冒充真实观测。相对路径以附件1目录为基准。后续脚本只按 sample_id 关联，不按表格行号猜测配对。

### 阶段0验收

- 标注表有效行数100、唯一 sample_id 数100、MP4数100，且表与文件路径集合一致。
- 每个样本有 SHA-256 和媒体探测状态；流缺失或解码失败列在 issues.jsonl，原始样本仍保留。
- 抽查至少3条：表格的 video_id/clip_id、原MP4路径与输出行完全相同。
- 输出再次读取后，字符串ID、原文和原标签未改变。

如 ffprobe 尚不可用，先完成标注与路径配对，再补媒体探测；不得将未探测时长标为“已核验”。

## 4. 阶段1：建立共同的原始时间坐标

### 时间定义

对样本 i，记视频首个有效显示时间戳为 P0_i。共同时间 t = 原流时间戳 - P0_i，单位秒。视频、音频均按此起点换算；保留未经平移的原始PTS和换算后的 t。不得默认音频从0秒开始。原始视频有效区间以实际显示时间范围确定，容器 duration 仅作交叉核对。

### 视频与音频时间

1. 用 ffprobe 或等价可复现工具提取帧级显示PTS；对缺失PTS、乱序PTS、可变帧率做显式状态记录。后续若固定频率抽帧，只在实有帧中选择最接近目标时间的位置，保存原帧序号和原PTS。
2. 用 FFmpeg 解出音频，记录流起始PTS、原采样率、重采样后的采样率和样本数。音频帧时间由起始PTS、采样率、窗长、步长计算；对应静音仍属于存在的音频观测。
3. 比较视频流和音频流的首末时间。存在前后空白或截断时，不把音频延展到视频无声部分；在时间索引中标注未覆盖区间。

### 文本时间

1. 只以标注表的英文 text 为被对齐转写。为强制对齐器可制作 normalized_text，但必须保存原文、规范化规则和词索引映射。
2. 在3条试运行视频上选择一个能接受给定转写的英文强制对齐工具，并固定工具版本、声学模型来源、检查点、运行参数与设备。优先选择能给出逐词起止时间、且能导出词与原文位置映射的工具。
3. 生成每词的 start_s、end_s、token_index、token_text、alignment_status。若工具不给置信分数，只保存状态，不人为制造置信度。
4. 对转写与音频不匹配的样本，保留词时间缺失与原因；可记录句段级时间范围，标记 alignment_level=utterance。不能把均匀分词时间写成真实词级时间。

### timeline JSON 合同

每条样本含 sample_id、video_origin_pts_s、video_duration_s、audio_start_offset_s、time_unit、video_frames、audio_frames、words、alignment_level、status、issues。每个时间事件含原始索引、原始PTS（若适用）、换算后起止秒数；词另含原文本词位置。大量逐帧数据可压缩保存，但读取接口保持一致。

### 阶段1验收

- 100个 sample_id 均有 timeline 文件或明确失败状态；不因单条失败中止全批次。
- 所有有效时间点单调、有限，并在视频区间内；允许的解码浮点容差写入配置与报告。
- 抽查短、中、长各一条的音频起点、视频帧PTS和至少一个词的时间位置。至少一条可展示词、声学帧和视频帧同轴关系。
- 无法得到可信词级时间的样本保留粗粒度状态；报告词级成功率及失败原因分布。

## 5. 阶段2：定义并提取三模态原始特征

### 先冻结特征契约

试运行前确定每个模态的特征名称、维度、时间粒度、缺失表示、工具与版本。对100条样本采用同一套提取器。原始特征的基本单元是“向量 + 对应原视频时间区间”；阶段2暂不生成统一50窗数组。

| 模态 | 首轮建议 | 时间关联 | 验证重点 |
|---|---|---|---|
| 文本 | 使用固定的英文预训练编码器，对完整转写编码后把子词向量聚合为词向量；不微调 | 词区间来自阶段1；词级失败则保留向量但标记时间不可定位 | 词数、子词到原词映射、相同文本重复编码的一致性 |
| 语音 | 以16 kHz为试运行采样率，25 ms窗/10 ms步长；提取帧级MFCC、对数能量、基频及其有效标记 | 声学帧记录真实起止时间 | 静音、无基频帧、重采样偏移、所有维度有限 |
| 视觉 | 以5 Hz为试运行抽帧率，优先提取可解释的人脸表情/关键点特征，同时记录人脸检测成功率 | 每个被选帧保留原帧号与显示PTS | 人脸缺失、多人脸选择规则、非均匀原帧间隔 |

这些是试运行初值，不是已验证的最佳参数。文本编码器与人脸提取器的具体实现取决于本机可安装性、3条样本的成功率、运行时间和文件大小。优先固定一个方案完成100条；如果更换方案，要全量重跑，不混合不同维度或不同模型版本。所有预训练模型只用于特征基础处理，禁止接入其他情感数据进行训练、微调或阈值选择。

### 文件与失败策略

每条样本保存一个压缩NPZ：text、audio、vision 三个二维 float32 数组及对应的时间数组和观测掩码。词级时间不可得时，文本向量仍可保存，但文本时间数组应以缺失状态表示，不生成伪时间。人脸未检测到的帧保留时间索引与 observed_mask=0；语音的无声帧与音轨缺失必须分开记录。配套 metadata/feature_index 记录模型版本、维度、原始序列长度、失败码和文件SHA-256。

不可把 NaN/Inf 留在输出数组里；确实没有意义的数值（如无声段的基频）用约定占位值加掩码表示。占位值本身不等于“真实观测为零”。不采用情感标签监督调整特征。

### 阶段2验收

- 100个 sample_id 均有 feature_index 行，能一一对应 stage0/manifest.csv。
- 成功的每条原始序列满足“特征行数 = 时间区间数 = 掩码长度”，各模态维度在全量样本中恒定。
- 所有数值特征可读取、有限；缺失与退化有可追溯状态。报告每模态成功率和原始有效长度分布。
- 复跑3条试运行样本，输出形状、ID与时间关系一致；若计算后端造成浮点差异，报告容差。
- 从至少一条样本的词/声学帧/视频帧特征行能回查原视频时间位置。

## 6. 环境与选型检查点

1. **媒体工具**：先安装或定位 FFmpeg 与 ffprobe，记录可执行路径、版本；阶段0媒体探测与阶段1解码必须使用同一可追踪版本。
2. **Python 环境**：建立独立环境并记录 Python 版本。阶段0只需标准库、openpyxl和媒体工具；numpy供阶段1—2数组处理。文本、语音、视觉依赖在3条样本试运行时再添加，避免提前安装不使用的大型库。
3. **试运行样本**：完成阶段0的时长统计后选最短、接近中位数、最长各一条；另可替换其中一条为音视频质量异常样本。每次选样规则留痕。
4. **选型冻结**：工具必须满足本规划的时间映射和文件契约。记录版本、模型来源、参数、推理设备、运行耗时、失败率，再批量运行100条。
5. **资源预算**：原始赛题视频不复制到工程；模型权重不重复打包。阶段2先估算全量原始特征与时间索引大小，为后续总附件≤50MB留余量。

## 7. 实施顺序与完成定义

按“环境检查 → 阶段0代码与验收 → 3条视频的阶段1 → 3条视频的阶段2 → 固定配置 → 100条批处理 → 全量验收”推进。每完成一个阶段，运行一次最小契约检查并保留输出报告。只有当阶段2的原始向量和原始时间索引稳定后，才进入完整解题流程的50窗对齐阶段。

本规划完成时只建立工程、配置和接口说明，不把任何计划中的脚本、特征或验收结果写成已完成。
