# 独立词边界核验操作指南

## 1. 这次核验什么

核验“某个词实际从第几秒开始、到第几秒结束”，不是再次判断整句转写是否正确。以前的6条Buzz文本复核仍保留；本次另建证据，不把旧的“人工通过”扩展成逐词时间准确。

工具：`src/independent_word_review.py`，只依赖Python标准库，已附中文注释。生成结果在本工程 `outputs/independent_word_review_v1/`。9条视频共233个原始转写词，按word、partial_word、utterance三种状态分别选择最短、中位、最长样本。属于目的抽样，不是随机抽样，不能将误差直接外推到100条总体。

## 2. 文件及分工

| 文件 | 用途 | 谁填写 |
| --- | --- | --- |
| samples.csv | 9条视频的相对位置、时长、词数及抽样依据 | 自动生成，勿修改 |
| reviewer_A.csv | 第一位核验者的独立判断 | 核验者A |
| reviewer_B.csv | 第二位核验者的独立判断 | 核验者B |
| adjudicated.csv | 两份标注完成后复听形成的最终参考 | 协商或第三人仲裁 |
| sealed_reference/automatic.json | 原有算法端点 | 标注完成前不要看 |
| protocol.json | 时间定义、原文件哈希、抽样规则 | 自动生成，勿修改 |
| check_00_pending/report.json | 初始空表的真实状态 | 233词待核验、误差null，不是通过 |

匿名代号用A、B、C，不填写真实姓名、学校或队号。工具只能检查代号不同，不能证明两人确实独立操作；独立性由团队负责。如果暂时只有一位核验者，可以先填A表，但不要假扮B或复制A表冒充第二人。

## 3. 按这个顺序操作

1. A、B各自领取对应空表和9条视频，不共享已填端点，不查看自动参考。原视频根目录是题目目录下 `E题数据/附件1-数据集原始多模态样本/MOSEI数据集部分原始视频-100条/`，后接samples.csv的relative_video_path。
2. 使用支持波形显示、循环播放和毫秒定位的本地音视频工具打开原素材。先完整听一遍，再放大波形并反复听词与前后文；波形峰值不是词边界的自动真值，须结合听觉判断。
3. 时间单位统一为秒，例如1.235。以原视频首帧为0；这9条源时间索引的video_origin_pts_s和audio_start_offset_s均为0。本批次可直接使用原视频/未裁切音轨的秒数。不要使用50窗序号、百分比或裁剪后归零时间；如截取小段，须加回截取起点。
4. 在A/B表中只填写status、human_start_s、human_end_s、reviewer_code、notes。保留sample_id、word_index、text、duration_s和全部行。CSV按UTF-8保存；使用表格软件时，将样本ID和文本列按文本导入，避免自动改写。
5. A/B均结束后，逐词比较两份表并复听争议位置，再填adjudicated.csv。不要自动取A/B平均；notes记录“复听确认”“两人一致”或具体争议处理依据。仲裁表不应参考自动端点。
6. 完成后运行下节命令；程序保留本轮三张人工表的快照及SHA256，输出统计，不回写原特征。后续修订使用新的check目录，保留旧轮次。

本批次可先试做最短的word样本 `-s9qJ7ATP7w/6.mp4`（5词、2.475秒），确认流程后再做其余8条。这个顺序仅降低上手成本，不得只报告做得好的词。

## 4. 每一行怎么填

| status | 意义 | 时间填写规则 |
| --- | --- | --- |
| pending | 还没核验 | 两个端点均留空 |
| matched | 原表中的这个词确实存在且可定位 | 0≤开始<结束≤视频时长 |
| text_mismatch | 原词与实际语音不匹配，无法可靠一一对应 | 不填端点；notes记录听到的内容及不匹配原因 |
| inaudible | 无法可靠听清或定位 | 不填端点；notes说明原因 |

示意（不是本题真实标注）：某词听辨为1.200—1.480秒，就填matched、1.200、1.480、A以及必要备注。不要照抄此示例。

Buzz纠正文本与附件原词不一致时，不改写附件，不硬按词序套用端点。保留text_mismatch记录；若以后要研究校正转写的特征，应新建处理版本、重提取并单独比较，不能覆盖本次原始词序参考。

## 5. 运行命令

在本问题工程根目录执行，`python`应指向可用的Python 3：

```powershell
python -X utf8 src/independent_word_review.py evaluate --bundle outputs/independent_word_review_v1 --output outputs/independent_word_review_v1/check_01
python -X utf8 -m unittest discover -s tests -p test_independent_word_review.py -v
```

如需重新建立一批空表，指定新的目录，不覆盖人工工作：

```powershell
python -X utf8 src/independent_word_review.py prepare --output outputs/independent_word_review_v2
```

输出目录已存在会报错，这是保护机制。标注尚未完成允许生成pending报告；重复、漏行、时间越界、同一人冒充双人、无理由排除、原词被改写或源文件变化均会拒绝评价。

## 6. 如何解读结果、写入论文

report.json分别报告仲裁状态数量、可比较词数、人工可定位但算法没有逐词端点的词数、端点绝对误差均值/中位数/P90、50/100/200毫秒内端点比例、逐样本结果、样本宏平均MAE和A/B分歧。误差符号定义为“自动端点−人工仲裁端点”，单位秒；P90采用最近秩定义。所有比例必须连同分母报告。

“词微平均”中每词两个端点等权；“样本宏平均”先计算每个有可比较词的样本MAE再等权平均。utterance及partial_word中无自动词边界的项不能冒充零误差，也不能因无法比较而从覆盖率说明中消失。文本不匹配、听不清应分别报告数量。

当前所有人工端点为空，报告没有科学精度结论。annotation_complete只表示仲裁表没有pending，不代表达到某个精度门槛；科学通过字段始终留空。即使只有少数可比词也不能宣称全部9条时间轴通过。填完后先检查可比较覆盖率和异常词，再决定能否写入问题一验证段。此目的样本不给出总体置信区间或“95%准确”的推广结论。

## 7. 与现有结果的边界

本工具不修改stage0—stage5任何文件，不重提取Buzz文本特征，不更新原有manual_review完成表，不训练问题二模型。AI辅助代码信息在程序文件头披露；具体历史版本与发布日期仍应以真实记录补齐。
